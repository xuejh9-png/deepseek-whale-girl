# 2026-10-28 中转站真实用量接入（已花费不再靠折算）

## 一、要解决的问题

桌宠卡片上的「已花费」一直显示 **$12.20**，而中转站后台是 **$20.10**。
两个数都"看起来对"，但对不上 —— 用户自然怀疑统计坏了。

根因不是算错，是**口径不同**：

| | 旧口径（本机折算） | 新口径（中转站实扣） |
|---|---|---|
| 数据来源 | `~/.claude/projects/**/*.jsonl` | `GET /v1/usage` |
| 统计对象 | 本机能读到的 Claude Code 请求 | 这把 Key 在中转站的全部请求 |
| 单价 | Anthropic 挂牌价（CC Switch 价目表） | 中转站实际结算价 |
| 结果 | $12.20 | $20.10 |

所以本轮直接把数据源换成中转站接口；本机折算降级为**接口不可达时的兜底**。

## 三、两个坑（实测证据）

### 坑 1：Python 默认 UA 被 Cloudflare 拦

```
$ python3 (urllib 默认 UA) → https://api.aishop520.com/v1/usage
HTTP 403  {"type":"https://developers.cloudflare.com/.../error-1010/","title":"Error 1010: Access denied"}

$ 换成 Chrome UA（同一台机器、同一把 Key）
HTTP 403  {"code":"unsupported_region","message":"本站暂不向中国大陆地区提供服务…"}
```

结论：默认 UA 连 WAF 都过不去（1010），换 UA 后才轮到地区判断。
所以 `provider_usage.py` 里 UA 是常量且写死，不是可选项。

### 坑 2：直连在国内网络被地区拦截 → 走本地转发层

本机 `ANTHROPIC_BASE_URL=http://127.0.0.1:8765`，那是一个本地转发层
（`~/.claude/relay/relay.py`，Safari TLS 指纹 + 系统代理出站）。
`GET http://127.0.0.1:8765/v1/usage` 返回 200，结构和直连完全一致。

所以候选地址按「上次成功的 → 配置里的 base → 直连」依次尝试，
成功过的地址记在磁盘上，重启后先试它，不必每次都撞一次地区拦截。

## 四、为什么费用和 CC 后台不一致（对账表）

同一天（2026-10-28）三份数据：

| 指标 | 本机日志折算 | 中转站 | 差 |
|---|---|---|---|
| 请求数 | 76 | 129 | 1.70× |
| 输入 token | 22,359 | 483,374 | 21.6× |
| 输出 token | 81,474 | 87,752 | 1.08× |
| 缓存写 token | 1,356,471 | 3,528,185 | 2.60× |
| 缓存读 token | 17,366,042 | 19,280,510 | 1.11× |
| 合计 token | 18,826,346 | 23,379,821 | 1.24× |
| 挂牌价 | $11.97 | $25.39 | 2.12× |
| **实际扣费** | — | **$19.48** | |

累计口径：本机 **81** 次 vs 中转站 **197** 次。

三层原因，按影响从大到小：

1. **覆盖不同（最主要）** —— 本机 `~/.claude/projects` 只有 13 个 jsonl，中转站记了 197 次。
   Claude Code 的一部分请求不落 transcript：`/private/tmp` 的临时会话、429 重试、
   长上下文 compact 摘要、子代理调用等。漏一次请求就同时漏掉它的 token 和费用。
2. **分量计数不同** —— 即使同一次请求，本地日志的 `input_tokens` / `cache_creation`
   也系统性偏小（输入 2.2 万 vs 48.3 万）。客户端记的是它自己看到的增量，
   中转站按上游 `usage` 记账，两边不是同一本账。
3. **计价不同** —— 挂牌价 `cost` ≠ 实扣 `actual_cost`，而且**不是固定倍率**：
   10-22 实扣是挂牌的 1.17×，10-26 是 0.30×，10-28 是 0.77×。
   说明中转站按自己的结算规则（缓存档位、折扣分组）逐笔计费，
   拿"官方单价 × token"永远算不出它。

**因此：** 只要还拿本机日志折算，就不可能和中转站后台对上；要对上只能问接口。
这也是本次改动的全部理由。

设计约束（为什么不做得更"全"）：

- **不阻塞**：网络请求在后台线程 + 60 秒缓存，`/state` 和 `/claude-cost` 永不等待网络；
  拿不到就给上一次的值（标 `stale`）或退回本机折算。
- **不猜**：没有 Key、接口报错、结构不认识，一律标原因并降级，不编数字。
- **只替换不累加**：Claude 那一栏整体替换成本接口的数，避免与本机日志重复计数。

## 八、已知限制

- 中转站的「今日」按它自己的账务日切分，和本机 0 点不保证一致；跨零点那一小时可能对不齐。
- `daily_usage` 只有三天（10-22 / 10-26 / 10-28），看起来是"有请求的日子才有行"，
  因此"本月"是按天明细求和，没请求的日子算 0，不影响总额。
- 接口没有分页/时间范围参数；历史超过它的保留窗口时，`total` 会小于真实历史。
