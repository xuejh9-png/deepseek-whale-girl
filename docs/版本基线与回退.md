|---|---|

## 出问题怎么回退（三种，按粒度）

```bash
cd ~/Desktop/WorkBuddy用量

# 1) 只回退素材（最常用）—— 从自动备份里取
ls assets/.backup/                      # 看有哪些时间戳
cp assets/.backup/<时间戳>/run.png assets/pet/run.png

# 2) 回退到基线这一版的所有文件（素材+代码+文档）
git checkout v1-run-good -- .

# 3) 整个项目回到基线（会丢弃基线之后的所有改动，慎用）
git reset --hard v1-run-good
```

回退后**必须**做两件事：

```bash
python3 build-manifest-js.py            # 同步 manifest.js（file:// 下要用）
open desktop/WorkBuddyPet.app           # 重启，让新素材生效
```

## 下一个版本怎么开工（不影响基线）

- 基线已经被 git 标签钉住，**后续所有改动都在 main 上继续追加**，
  不会动到 `v1-run-good` 指向的那份内容。
- 新素材**必须先通过验收**才会被换进 `assets/pet/`：
  `intake-assets.py` 会先做"合并后全集"的验收 + 零告警检查，
  不通过就**不安装**、并保留旧版（还会自动备份一份）。
- 所以"做坏了导致她现在变难看"这件事，机制上已经挡住了。
