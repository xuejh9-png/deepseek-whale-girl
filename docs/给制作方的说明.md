跑步素材 `run.png` 需要改一版。**帧数、帧率、规格全部不用动**，只改画面内容。

## 一、要改的三件事（按重要程度排序）

### 1️⃣ 十二帧的角色尺寸必须一致（最重要）

**问题**：整只角色在不同帧里被横向压窄了。实测同一张图里：

```
#1 202px(100%)  #2 204px(101%)  #3 192px(95%)   #4 183px(91%)
#5 158px(78%)   #6 204px(101%)  #7 174px(86%)   #8 192px(95%)
#9 182px(90%)   #10 158px(78%)  #11 200px(99%)  #12 202px(100%)
```

（百分比 = 角色宽度相对站立姿势）

**为什么确定是"被压窄"而不是"画小了"**：角色高度全程都是 250~254 像素没变，
但宽度差最多 22%，而且头、上身、下身**一起**变窄、比例一致。

**为什么不可能只是打包/导出问题**：同一张图里第 1/2/6/11/12 帧是 100%、
第 5/10 帧是 78%。整体缩放不可能只影响部分帧。

**为什么也不能解释成"画成 3/4 侧面"**：3/4 转向会让整段循环**稳定**略窄；
而现在是 `100→95→91→78→101→86→95→90→78→99→100`，
**一个 0.75 秒的循环里收窄又展开两次**。角色是直线往前跑，
不可能一步之内转过去又转回来。

**要求**：12 帧的角色大小必须和站立姿势一致（任何一帧不低于 **88%**）。
腾空只改变**位置**，不改变**大小**。最窄的是**第 5、10 帧**，从那两帧查起。

### 2️⃣ 两次腾空的间隔要相等

现在腾空在第 **5 帧和第 10 帧** → 间隔是 **5 帧 / 7 帧**。
两步循环里应该**各 6 帧**（例如第 4 和第 10 帧）。

换算成时间：**0.31 秒 vs 0.44 秒**，一条腿的步时比另一条长 40%，细看会有点"跛"。

### 3️⃣ 触地那一下要"压低"

现在接地帧的脚底高度是 **353~355，只差 2 像素**，等于全程一样高。

**要求**：触地/压低那几帧的脚底比其它接地帧低 **2~6 像素**，
配合重心下沉 —— 这是"落地缓冲"的重量感来源。

## 二、改完放这里

**打包成一个 zip，丢到桌面（或下载目录）就行。** zip 内部按项目结构放：

```
assets/pet/run.png        ← 就这一个文件（manifest.json 不用给，规格没变）
```

不要只丢一个裸的 `run.png` 在桌面上 —— 接收程序只认 **zip 包**
或 **名为 `pet` 的文件夹**，裸文件会被忽略。

- 文件名**必须**是 `run.png`（小写、`.png`、不加 `-v2`、不加日期）
- 不是同一台机器的话，把 zip 发我，我放到桌面

## 四、规格（不要改，改了运行时会错位）

| 项 | 值 |
|---|---|
| 单格画布 | **320 × 400** |
| 排布 | **6 列 × 2 行**（12 帧，行优先）|
| 帧率 / 循环 | 16 fps，1–12 帧整体循环 |
| 角色显示高 | 256px（占画布 64%）|
| 水平中心 | x = 160 |
| 脚底接地线 | y = 358 |
| 背景 | 四角必须全透明，不要画棋盘格/白底 |
| 朝向 | 保持"向右侧视角"；向左跑由程序水平翻转，**不要另画一版** |
